# 08. Замок владельца для мерок и журнала

**Проблема (D2).** Мерки — глобальная запись, сайт публичный: первый посетитель перезапишет мерки владельца. Хуже: чат подставляет мерки в ответы **любому** посетителю.

Это минимальная мера, а не система аккаунтов: «сайт = один владелец». Выбор модели с несколькими пользователями (B7) остаётся за вами.

## Решение

- `OWNER_KEY` **не задан** → всё работает как раньше (обратная совместимость).
- Задан → `middleware.ts` закрывает `/api/measurements`, `/api/sewn`, `/measurements`, `/journal`: API отвечает `401`, страницы ведут на `/owner`.
- `/owner` — форма ввода ключа → `POST /api/owner` → httpOnly-cookie (`SameSite=Strict`, `Secure` в проде, 90 дней).
- Сравнение ключа за постоянное время (`safeEqual`, без `node:crypto` — работает на Edge).
- Подбор ключа: 5 попыток за 5 минут с адреса.

## Обязательный второй шаг: чат

В `api/chat/route.ts` мерки подставлять только владельцу:

```ts
import { requestIsOwner } from "@/lib/owner";
const useMeasurements = requestIsOwner(req); // дальше — как раньше, но только при true
```

Это же значение передаётся в `isCacheable({ usesMeasurements })` (см. 05).

## Компромиссы

- В cookie лежит сам ключ: для одного владельца и httpOnly это приемлемо; для нескольких людей нужны сессии — это уже B7.
- `X-Forwarded-For` берётся от Caddy; без доверенного прокси лимит попыток обходится подменой заголовка.
- История диалогов и оценки не закрыты: они не содержат мерок. Если решите закрыть — добавьте путь в `matcher`.
