# 09. PWA и офлайн-каталог

**Закрывает:** B13. Сценарий: швея в магазине тканей, сети нет.

## Решение

- `app/manifest.ts` + иконки 192/512 и maskable (`public/icons`), `app/icon.svg`.
- `public/sw.js` — без библиотек, ~50 строк:
  - страницы: сеть первой, при сбое — копия из кэша, иначе `/offline`;
  - `/_next/static/` — кэш первым (имена файлов содержат хэш);
  - **никогда не кэшируются** `/api/`, `/measurements`, `/journal`, `/owner`, `/assistant`;
  - прогрев каталога: по сообщению `warm` скачивает страницы пачками по 6.
- `RegisterSW` регистрирует worker только в production и пропускает прогрев при включённой экономии трафика (`saveData`).
- Версия кэша `shveyka-v1`: смена константы сбрасывает старые копии.

## Подключение

`app/layout.tsx` подключает `<RegisterSW />`. Список страниц для прогрева
компонент берёт сам из `/sitemap.xml` — на устройстве, в браузере:

```tsx
// внутри <body>: <RegisterSW />
```

Так список всегда совпадает с каталогом, и сборке не нужна база: `layout`
с обращением к базе заставил бы `next build` требовать доступную БД, а в CI
базы нет.

Прогрев — 57 страниц, порядка 2–3 МБ один раз на устройство.

## Проверка

`pnpm build && pnpm start` → DevTools → Application → Service Workers → Offline → открыть ранее виденную ткань. Lighthouse должен засчитать installable PWA.

## Ограничения

Помощник и калькуляторы с обращением к API офлайн не работают — это каталог, а не вся функциональность. Нужны HTTPS (Caddy уже даёт) и `NEXT_PUBLIC_SITE_URL`.
